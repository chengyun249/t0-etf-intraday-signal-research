# A股T+0 ETF分钟级信号研究：项目介绍

## 一、项目概述

本项目围绕A股市场中支持T+0交易的ETF，研究1分钟OHLCV数据中是否存在能够覆盖交易摩擦、并在严格样本外验证下保持稳定的日内信号。

与单纯寻找高收益回测不同，本项目把研究重点放在三个问题上：

1. 分钟级价格和成交量数据是否包含稳定的短周期预测信息；
2. 统计上可识别的信号能否在买卖成本、滑点和保守成交假设下转化为经济收益；
3. 当策略没有通过检验时，能否明确区分信号失效、样本不足、成本过高和数据粒度不足等原因。

当前版本为v2研究框架。它适合作为量化研究、课程项目和方法验证案例，**不是可直接部署的实盘交易系统，也不构成投资建议**。

## 二、研究背景

A股普通股票和大多数股票ETF实行T+1交易，而部分跨境、商品、债券和货币类ETF支持T+0。理论上，这类产品允许日内多次交易，更适合研究开盘突破、短周期动量、均值回归和相对价值等信号。

但T+0并不意味着策略天然具有优势：

- ETF日内波动通常小于个股，单笔潜在收益较薄；
- 分钟级策略对佣金、买卖价差、滑点和市场冲击非常敏感；
- 1分钟K线无法还原bar内价格路径和真实排队成交；
- 可交易ETF数量有限，横截面样本较小；
- 相邻分钟标签高度重叠，不能把每条分钟记录视为独立样本；
- 不同ETF的T+0资格、跨境额度、申赎和停牌状态会随时间变化。

因此，本项目不预设“高频或机器学习一定有效”，而是通过保守执行和时间隔离验证来检验信号是否真正可交易。

## 三、研究范围

### 3.1 数据口径

- 频率：1分钟OHLCV；
- 研究对象：候选集中支持T+0的A股ETF；
- 主要数据源：Tushare；
- 当前v2本地复跑：2025年30只ETF，共1,756,890条分钟记录；
- 开发期：2025年1月至8月；
- 锁定测试期：2025年9月至12月；
- 主成本假设：单边2bp；
- 成本压力测试：单边0/1/2/3/5/10bp。

仓库不包含私有原始行情。历史2022—2024样本产生的旧报告仅保留为格式示例，不能与v2修正结果直接比较。

### 3.2 研究信号

项目覆盖以下信号和组合方式：

- 开盘区间突破（Opening Range Breakout，ORB）；
- 基于历史噪声边界的运动空间过滤；
- VWAP偏离和均值回归；
- ETF类别广度与相对强弱；
- 配对价差与相对价值；
- ORB、Noise与Relative Value组合信号；
- walk-forward参数选择；
- purged/embargo机器学习诊断。

组合信号中的 `movement_budget_bp` 只表示观察到的运动空间是否足以覆盖成本门槛，不代表条件期望收益，也不应被称为“预期Alpha”。

## 四、研究方法

### 4.1 严格的信息时点

信号在分钟 `t` 收盘后形成，最早只能在分钟 `t+1` 开盘成交。入场后的止损和状态变量只能使用当时已经完成的数据。例如，累计VWAP和追踪止损高水位均滞后一根bar，避免使用当前bar尚未知的信息。

### 4.2 保守的OHLC成交模型

由于分钟K线没有逐笔路径，执行模型采用偏保守的假设：

- 跳空越过止损价时，按更差的当前分钟开盘价成交；
- 盘中止损默认额外计入1bp不利滑点；
- 同一根K线同时触及止盈与止损时，按止损先发生处理；
- 追踪止损只使用上一根已完成bar形成的高水位；
- 所有收益统一记录毛收益、成本和净收益，防止成本口径混用。

这些设定降低了过度乐观程度，但仍不能替代买一卖一报价、盘口深度或逐笔成交回放。

### 4.3 动态标的池

日期 `d` 的可交易标的只能根据 `d` 之前的历史长度和成交额确定。滚动成交额统计先进行时间偏移，避免用当日尚未完成的信息选择当日标的。

需要注意：动态筛选只能在已经下载的候选集中进行。若下载阶段事后只保留了少量ETF，后续代码无法恢复当时未下载的历史合格标的。

### 4.4 Walk-forward与模型验证

- 参数默认按周更新，避免每日重新选择造成过度追踪噪声；
- 候选参数至少需要30笔历史交易并覆盖20个交易日；
- 单只ETF至少需要10笔交易；
- 参数排名使用按交易日聚类的单侧90%平均净收益下置信界；
- 机器学习按完整交易日分块，训练和验证之间设置purge与embargo；
- ETF代码不作为数值特征，避免模型记忆具体证券身份；
- 结果按折和交易日汇总，避免把重叠分钟标签错误地当作独立证据。

## 五、v2修正内容

新版针对原项目中可能导致收益高估或结果难以维护的问题进行了重构：

- 修正VWAP、止损和追踪止损的信息时点；
- 加入跳空感知、不利滑点和止损优先的执行规则；
- 将含义容易被误读的收益代理改名为运动空间指标；
- 建立point-in-time动态标的池；
- 用按交易日聚类的收益下置信界替代奖励profit factor的参数选择；
- 提高候选策略最低成交笔数和日期覆盖门槛；
- 机器学习验证改为按完整日期进行purge和embargo；
- 统一成本网格和指标定义；
- 将轮动原型、旧脚本和大型重复文件移出发布仓库；
- 增加无私有数据单元测试、失败实验记录和策略验收报告。

## 六、当前结果

修正后的2025年复跑中，`commodity_focus` 是开发期收益下置信界最高的候选，但其按交易日聚类的90%平均净收益下置信界仍为 **-6.16bp**，因此没有任何研究范围通过开发期选择门槛。

作为诊断，固定组合在锁定测试期产生28笔交易，分布于19个交易日：

| 单边固定成本 | 平均单笔净收益 | 解释 |
|---:|---:|---|
| 0bp | 7.37bp | 仅说明存在毛收益空间 |
| 2bp | 3.37bp | 平均值为正，但统计证据不足 |
| 3bp | 1.37bp | 边际为正 |
| 5bp | -2.63bp | 成本压力下转负 |

在单边2bp成本下，按交易日聚类的5日移动区块Bootstrap给出的年化日均收益95%下界为 **-0.49%**。这意味着现有样本不能排除真实期望收益为零或为负。

因此，正确结论不是“已经找到盈利策略”，而是：

> 当前信号在低成本假设下表现出有限边际，但开发期门槛、样本量、置信下界和高成本压力测试均不足以支持部署。

|---|---|
| 开发期存在90%净收益下置信界大于0的候选 | 未通过 |
| 至少100笔锁定样本外交易 | 未通过 |
| 至少60个发生交易的样本外日期 | 未通过 |
| 2bp成本下区块Bootstrap 95%下界大于0 | 未通过 |
| 3bp单边成本下平均单笔净收益为正 | 通过 |

## 九、复现方式

建议使用Python 3.11：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m pytest -q
```

典型研究流程：

```bash
python src/01_download/download_t0_etf_1min_2022_2024_v2.py
python src/02_build_panel/build_t0_intraday_bar_panel_2022_2024.py
python src/03_backtest/backtest_combined_orb_noise_rv_2025.py
python src/03_backtest/backtest_combo_walk_forward_daily.py
python src/04_diagnostics/train_purged_signal_models.py
python src/04_diagnostics/evaluate_strategy_acceptance.py
```

下载数据时通过环境变量提供凭据：

```powershell
$env:TUSHARE_TOKEN = "your-token"
```

请勿把Token、`.env`、私有行情、模型产物或本地归档提交到Git仓库。

## 十、已知限制

1. 1分钟OHLC无法识别bar内真实价格路径；
2. 缺少买一卖一、盘口深度、逐笔成交、订单延迟和冲击成本数据；
3. 当前测试只有28笔交易和19个交易日，统计功效很低；
4. 动态股票池仍受限于事先下载的候选ETF集合；
5. T+0资格、跨境额度、申赎、停牌等状态尚未完全point-in-time化；
6. long-only策略无法直接利用负向预测，配对和卖空又受到实际交易约束；
7. 历史失败实验较多，多重比较风险不能仅靠单次Bootstrap消除。

## 十一、后续工作

- 下载每个历史时点完整的合格T+0 ETF候选集；
- 获取买卖报价、盘口或逐笔成交数据，重建可成交价格；
- 在不继续查看当前测试结果的前提下，累计至少100笔、60个交易日的独立样本外交易；
- 预先冻结信号、参数和验收门槛，再进行新市场阶段复验；
- 加入ETF额度、申赎、停牌、费率和容量约束；
- 对跨境、商品和债券ETF分别建模，避免混合不同微观结构；
- 研究更适合日内交易的风险过滤和仓位控制，而不是只优化入场信号。
